Both apps update this time: Android **0.9.0 → 0.10.0**, Mac **0.9.0 → 0.10.0**. Install both — the new file-transfer behaviour needs each side. (An older app on either end keeps working; it just doesn't get the new parts.)

## Sending files no longer crashes the Mac

If dropping a file on the Mac app ever made it quit — especially a second file, or several at once — that was this. A file sent from the Mac that was smaller than about 640 KB never got a receipt from the phone, so the Mac waited 30 seconds, reported a false "your phone stopped responding", and was left in a state that crashed the next transfer. Both halves are fixed: small files are acknowledged properly, and a transfer that ends early can no longer take the app down.

## Several files and whole folders

### From the Mac

- **Drop as many files as you like.** They go out one after another as a single batch, under **one progress bar**. The label names the file in flight with its own progress — `report.pdf (50%)` — and a `3 / 5` counter shows where you are in the batch. Drop more while it's running and they join the batch. There's a **Cancel** button.
- **Drop a folder.** It arrives on the phone with its structure intact, under `Downloads/Link to Mac/<folder>/…`. Hidden files and shortcuts inside it are skipped, and a folder is capped at 1,000 files.
- **One notification at the end**, not one per file: "7 files sent to your phone", or "4 of 5 sent" with the reason when something didn't go through. It now also appears while the Mac app is in front, which it didn't before.

### From the phone

- **Select several photos or files and share them** with **Send as a File** — they go out in order under one progress notification (`Sending 2/5` · `name.ext (50%)`) and finish with one message.
- Files that arrive on the phone in a burst are collected into a **single notification** ("7 files", or "4 files in Photos") instead of one for each.

## "Sent" now means saved

The receiving side used to acknowledge the last piece of a file *before* writing it, so a file that couldn't be saved — a full disk, a refused write — was still reported as delivered. Now the final acknowledgement waits for the file to be on disk, and a file that can't be saved is reported as failed straight away, with the reason, instead of after a 30-second wait.

## Also fixed

- **Switching between Wi-Fi and the relay mid-transfer** now moves the file onto whichever link is up, or ends the transfer immediately if there is none — it used to keep sending into a dead link until it timed out.
- **A phone that vanishes mid-transfer** no longer leaves the Mac's "receiving" row on the dashboard forever; it clears itself.
- **Large files received on the Mac** are written in the background, so the window no longer freezes while a big one is saved.
- A very long file name no longer breaks the transfer, and an existing file is never overwritten.

## Known limitations

- **Finder ▸ Share ▸ "Send to Phone" still does not work.** macOS refuses to run an app extension that isn't signed with an Apple Developer certificate, and this app is deliberately unsigned. Use drag-and-drop.
- **Dragging from Mail, Photos or Safari's download list** isn't supported — those hand over a promise of a file rather than the file. You'll get a notification saying so; drop the file from Finder instead.
- **64 MB per file.** Larger files are skipped, with a message.
- Folders sent *from the phone* aren't supported yet (the phone's share sheet only sends files).

## Install

**Android:** sideload `linktomac-preview-0.10.0.apk`.
**macOS:** existing installs update themselves via Sparkle; new installs open `LinkToMac-0.10.0.dmg` (right-click → Open, since the app is unsigned).
